Class RAG Benchmark

A plug-and-play benchmark that every student runs on its own Raspberry Pi, whatever its architecture. It scores your system on open datasets that already have published state-of-the-art results, records the Pi's health while it works, and keeps the bill small.

~1.15 GBdata on the Pi, 3 packs
7eval axes, no two measure the same thing
~1.5 hone official run on a Pi 4, judged overnight
~$4.70per person, all testing, flash-class model, comparable to published results
Layer 1 · Retrieval

Did it find the right evidence?

question → ranked pages

No language model involved. Scored against gold evidence pages.

Layer 2 · Generation

Given the right evidence, is the answer right?

question + gold pages → answer

Retrieval switched off. Any error left is the generator's.

Layer 3 · End-to-end

Does the whole system answer, cite and not make things up?

documents + question → answer + citations

Your real pipeline, as it runs on demo day.

Datasets

Three packs, and why these

A dataset made the cut only if it passed all six checks:

  1. Open license, so the whole class can download and use it.
  2. Published SOTA results, so you can tell whether your system is good or bad.
  3. Gold evidence pages and gold answers, so the three layers can be scored apart.
  4. Fits the Pi: about 1 GB in total, and no OCR or captioning tokens at ingest.
  5. Looks like demo day: real documents, charts, tables, answers spread over pages.
  6. No overlap: each pack tests something no other pack tests.

ViDoRe V3 · Human Resources

442 MB14 docs1,110 pages318 questionsCC-BY-4.0

Why

  • EU labour-market reports full of charts and tables
  • Each page ships as an image and as extracted markdown (~780 tokens), so text and image systems both enter
  • Gold pages (~5 per question) and gold answers
  • Live MTEB leaderboard; answer results in the ACL 2026 paper

Weak points

  • Questions partly LLM-generated, then human-checked; real people phrase things more loosely

ViDoRe V3 · Computer Science

513 MB2 docs1,360 pages215 questionsCC-BY-4.0

Why

  • Long textbooks with equations, code and figures
  • A different kind of content from HR: dense, technical, few documents but many pages
  • Whole task used, so the published per-task numbers still apply

Weak points

  • Only 2 documents, so few distractor files (the Pharma task has 52 but adds ~240 MB)

CRAG · fixed subset

~200 MB400 of 1,335 public-test questions5 web pages eachCC BY-NC 4.0

Why

  • The only benchmark that scores a made-up answer (−1) below "I don't know" (0), so hallucination is measured directly
  • Includes false-premise, time-sensitive and multi-hop questions
  • Noisy HTML pages stand in for "use the web when the documents are not enough", offline and identical on every Pi
  • Published results from industry systems and the KDD Cup 2024

Weak points

  • Web QA from 2024, not document QA; use the official release, not the Apache-licensed mirror
  • Pages are shipped with scripts and styles removed to stay near 200 MB (raw HTML would be over 1 GB)
  • The paper never released its judge prompt, so CRAG scores are close to the paper's, not exact

Layer 1 · axis 1

Retrieval quality: can the system retrieve the correct documents?

If the evidence never reaches the model, no model can answer. This layer costs no tokens and tells you whether to work on search or on prompting.

Input / output

  • In: question text
  • Out: top-10 page ids, best first
  • Gold: the benchmark's evidence pages

Metrics

  • nDCG@10: rewards putting the gold page near the top; the leaderboard metric
  • Recall@10: share of gold pages in your top 10

Comparable because

  • Whole HR and CS tasks, every English query, same metric; compare with the English rows. Newer retrievers on the MTEB leaderboard may score higher

Layer 2 · axis 2

Generation quality: is the answer accurate and grounded in the context it was given?

The harness sends the gold pages straight to your generator and your own search is switched off. Errors here are reading, reasoning or prompt problems, never search problems.

Input / output

  • In: question + gold pages (markdown, images, or both, as your system normally sends)
  • Out: answer text

Metrics

  • Accuracy: share judged "Correct" by GPT-5.2 (medium reasoning) with the paper's judge prompt (Figure 24)

Why

  • The paper publishes accuracy with perfect retrieval, so the ceiling is known

Layer 3 · axes 3 and 4

End-to-end quality: does the full pipeline answer correctly, give evidence, and avoid hallucination?

This is what the checkers see. It adds ingest, the agent loop, time limits and citations on top of Layers 1 and 2. Correctness on documents is axis 3 (ViDoRe); hallucination is axis 4 (CRAG).

Input / output

  • In: the pack's documents (ingested once), then the questions
  • Out: answer + cited pages

Metrics

  • Axis 3: accuracy, citation precision (cited pages that are gold)
  • Axis 4: truthfulness, hallucination rate, missing rate

Comparable because

  • ViDoRe: a fixed random sample of the English questions, the paper's judge and prompt
  • CRAG: a fixed random sample of the public test set and CRAG's own auto-eval scoring, judged by the two model families the paper used
  • Every score carries its 95% error bar (see Sampling)

Plug and play

Running it on your Pi

  1. Install. Clone the benchmark repo on the Pi and run ./install.sh. It downloads the three packs, checks their sha256 sums and checks for 2.5 GB of free disk.
  2. Expose your system. Run a small HTTP server with three endpoints, in any language: POST /ingest {dir}, POST /retrieve {q, k} returning page ids, and POST /answer {q, context?} returning {answer, cited}. Stream the answer (server-sent events or chunked text) so the harness can time the first token; a non-streaming server is scored with first token = total time.
  3. Count tokens honestly. Point your LLM client's base URL at the harness's local proxy (any OpenAI-style API). It counts tokens and cost itself, so nobody self-reports.
  4. Run. crb run --adapter http://localhost:8000 runs every axis and writes results.jsonl, health.csv and report.html with your numbers next to the SOTA rows. crb run --smoke runs retrieval (free) plus 30 LLM questions with a cheap judge for development; crb run --official runs the full comparable protocol.
  5. Compare. crb baseline runs the shared reference system (BM25 over the page markdown + one fixed cheap LLM) as a floor to check your setup against.

Axis 7

Pi health, sampled every second

A system that is fast for five minutes and then throttles will lose the demo. The sampler runs for the whole benchmark, so a full run doubles as a heat soak test.

Sampling

Why a sample still compares with SOTA

A random sample from the full question set estimates the full-set score with no bias: on average it is neither higher nor lower. What sampling adds is uncertainty, shown as a 95% error bar. Your score is compared with a published number by checking whether the published number falls inside your bar.

Every student gets the same fixed sample, so the class instructions, seed and error bars are the same for all.

  1. Random, stratified, one published seed. The sample keeps the full set's mix of question types (chart, table, multi-hop, numerical). The question ids are in the repo.
  2. Drawn once. Never redraw until a score looks good, and never tune on the sample.
  3. Same protocol as the paper. Same judge, prompt and scoring. Only the number of questions changes.
  4. Always report the error bar. "Beats SOTA" needs your whole bar above the published number; "below SOTA" needs it all below.

Reading your results

Which layer broke

Every ViDoRe question gets exactly one tag. The share of each tag tells you where to spend your next week.

Retrieval miss

L1 fail

No gold page in your top 10. Fix search, chunking or parsing first; a better model will not help.

Generation miss

L1 pass · L2 fail

The model had the right page and still got it wrong. Work on the prompt, the model, or what you send (text vs page image).

Integration miss

L1 pass · L2 pass · L3 fail

Each part works alone, the whole does not: loop stopped early, time limit, context too long, answer cut off.

Fair comparison

Rules every run follows

  1. Benchmarks are test sets, never tuning sets. Tune on your own data; run the benchmark only to measure. Demo day uses documents nobody has seen.
  2. The papers' judges, for everyone. ViDoRe: GPT-5.2, medium reasoning, the paper's judge prompt. CRAG: average of a gpt-3.5-turbo and a Llama 3 70B-class judge with CRAG's scoring (the exact 2024 versions are no longer offered). The harness calls them with the class key, so no one grades their own run.
  3. One fixed sample for everyone. Official run: 100 HR + 100 CS ViDoRe questions and 400 CRAG questions, stratified by type, seed and ids in the repo; retrieval always uses all 533. --full runs every question for close-margin claims.
  4. Run on your demo Pi. Latency and health count only from the device you demo on.
  5. One official run per person, with error bars. Published numbers are single runs too. The report gives each score with its 95% interval, so small differences are not over-read.
